About me

I build backend systems that keep running.

I'm a Python developer based in Heilbronn, Germany. Most recently I owned the pipeline that turns customer CAD data into rendered images for YOLOv5 training, running on a fleet of Linux servers with production-level uptime. Outside of work I build distributed systems from scratch (message brokers, caches, rate limiters, vector search) because it's the best way I know to understand how they really behave under load.

~40% faster rendering after migrating the service to a newer Blender version
99%+ uptime on a horizontally scaled rendering service
5+ Linux servers operated with Ansible, containers and GPU assignment
5 → 2–3 days to onboard a new customer, down from about 5, through automation

What I've done

  • Owned a data pipeline end to end: validating, transforming and uploading customer CAD datasets, then feeding the renders into model training.
  • Made it faster and steadier: mesh reduction on incoming STL files and a Blender upgrade each gave roughly 40% more render throughput.
  • Ran it in production: scaled the deployment layer with Ansible and served as the main technical contact for incidents and customer requirements.

How I work

  • Measure first. My Search Engine and Rate Limiter projects ship with benchmarks, so design choices come with numbers.
  • Test and automate. Pytest, ruff, mypy and GitHub Actions CI run on every project I publish.
  • Own the architecture. I use AI coding tools (Claude Code, Cursor) daily, but I decide the design, the data flow and the backend.
  • Communicate clearly. I'm comfortable diagnosing a failure live and then explaining it to a customer.
